# Stage127 — прокрутка истории сетевого чата на телефоне

**Дата:** 22.11.2026. **GAME_BUILD:** 127. **MP_VERSION:** 43 — без изменений.

## Что требовалось

При входе в поле ввода Android открывает клавиатуру, а чат уменьшает видимую область так, чтобы строка ввода оставалась выше клавиатуры. После этого история сообщений над строкой ввода должна **свободно листаться пальцем вверх/вниз**, как при открытой, так и при закрытой клавиатуре. История не должна перескакивать к последнему сообщению, пока игрок читает старые.

## Что изменено

1. **Нативный touch-scroll остаётся на истории.** История — независимый `overflow-y:auto` с `touch-action:pan-y`, `overscroll-behavior:contain`, `-webkit-overflow-scrolling:touch`; контейнер чата и строка ввода не перехватывают жест прокрутки.
2. **Таймеры и сетевые обновления больше не пересоздают историю без изменений.** `mpChatRender` сопоставляет идентификаторы строк, сохраняет DOM-элементы при обычном повторном вызове и добавляет новые сообщения без замены уже отображённых строк, включая удаление самой старой записи при достижении лимита 100 сообщений. Совпадающие DOM-элементы сохраняются даже при сдвиге окна истории.
3. **Чтение старой истории не прерывается новым сообщением.** Касание/колесо мыши/клавиатурная прокрутка отмечают режим чтения. Автоматический переход к концу отключён до тех пор, пока игрок не долистает вниз. При изменении окна истории и реконструкции сохраняется положение ближайшей сохранившейся строки.
4. **Обычный порядок UI неизменен:** заголовок → сообщения → форма набора. Клавиатура сдвигает/сжимает окно только через механизм Stage126 (`visualViewport`, `VirtualKeyboard`, осторожный запасной предел). При увеличении истории строка ввода не сдвигается.
5. **Маленькие экраны:** при очень маленькой высоте и активной клавиатуре заголовок и форма компактнее, чтобы осталось больше места для жестов. При экстремально малой видимой высоте доступная область истории неизбежно мала.
6. **Чистая история другой комнаты:** сброс сетевого чата очищает старые DOM-строки, предотвращая показ сообщений от предыдущей комнаты до получения новых.

Изменены только `src/21j-multiplayer-traffic.js`, `styles/55-multiplayer.css`, версия сборки в `src/00-core-save.js`, документация и тесты. **WebRTC-протокол, каталог карт, столкновения, графика, режим PvP и кампания не изменены.**

В каждом случае: клавиатура открыта/закрыта, жесты в двух направлениях, сохранение позиции при повторном рендере, новое сообщение, Unicode и закрытие.

## Что нельзя подтвердить автоматически

Физический Android/IME (в особенности открытие `content://` через мессенджер), GPU WebGL и реальные соединения нескольких устройств **не тестировались**. Headless Chromium не открывает настоящую Android-клавиатуру; её геометрия имитируется. На крайне низком браузерном окне 360×280 резервная область над неизвестной клавиатурой может быть недостаточной для удобного жеста; горизонтальный 800×360 проверен нативными свайпами.

### Как проверить вручную на телефоне

Открой комнату и чат. Получи 20+ сообщений. С закрытой клавиатурой проведи пальцем по истории вниз (к старым сообщениям) и вверх (к новым). Нажми в поле ввода, чтобы открыть клавиатуру: поле должно оказаться над ней, и те же жесты по области истории должны прокручивать только историю. Пока ты читаешь старые сообщения, пусть второй игрок отправит новое — не должно перебросить тебя вниз. После прокрутки к концу новые сообщения снова должны показываться внизу.
