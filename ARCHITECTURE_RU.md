# Технический паспорт модульного проекта

## Базовый принцип

Логика исходной версии полностью сохранена: 28 модулей в `src/` являются последовательными сегментами единой самовызывающейся JS-функции. При сборке они **конкатенируются без перестановки**. Сборщик вставляет в шаблон CSS и скрипт, получая **полностью автономный `index.html`**. Для разработчика также собирается `dist/game.js`, а `dev.html` подключает его и стили как отдельные файлы.

`index.html` и `dist/game.js` **генерируются**. Их нельзя редактировать как основные исходники: правки будут потеряны при следующей сборке. Рабочие файлы — `src/*.js`, `styles/*.css`, `tools/index-template.html` (только если сознательно меняем HTML-разметку).

## Критические связи кода

- `src/00-core-save.js` — начальные переменные `game` и `save`, схемы сохранений, импорт/экспорт. Контракт JSON и ключи localStorage менять только с миграцией.
- `src/01-webgl-shaders.js` — инициализация WebGL, материалы, шейдеры и постэффекты. Поддерживать Canvas fallback из `src/11-fallback-render.js`.
- `src/03-height-and-collision.js` + `04-map-generation.js` + `05-world-mesh.js` — совместно задают геометрию этажей, коллизии, лестницы, мосты, меши; вносить изменения согласованно.
- `src/07–09-robot-foundry-*.js` — генераторы и оснастка роботов, анимация, разрушение и обломки. Связаны с AI, уроном, рендером, звуком.
- `src/12-arsenal-and-game.js` — справочники оружия, врагов, улучшений, вход в сектор.
- `src/15-mission-system.js` + `16-mission-devices.js` + `21-campaign-map.js` — типы и состояние миссий, условия завершения, выбор уровней, страницы глав.
- `src/17-weapon-combat.js` + `18-ai-and-abilities.js` — боевой цикл, оружие, умения, враги и снаряды.
- `src/19-gameplay-update.js` + `20-minimap-and-checkpoint.js` — игровой тик, HUD, навигация, реальный чекпойнт.
- `src/24-cinematic-hooks.js` и `25-cinematic-menu-perf.js` — **обёртки, которые намеренно ПЕРЕНАЗНАЧАЮТ ранее объявленные функции** (`render`, `update`, `menu`, `pause`, `damagePlayer`, `awardKill` и другие). Порядок имеет значение: не перемещать эти участки без анализа.
- `src/26-input-handlers.js` + `27-main-loop-diagnostics.js` — ПК/сенсорные события, полномасштабный режим, фактический FPS и тестовые API. В конце выполняется инициализация игры.

## Эталон, контроль и регрессии

Исходный файл `reference/NEON_RIFT_3D_FPS_CONTROL_ORIGINAL.html` сохранён без изменения. Для первой модульной версии: **весь готовый `index.html` равен исходнику побайтово**, не только по логике. Прогон интеграционной синтаксической проверки и автоматических проверок доступен в `tests/`; набор для Chrome с Playwright — `tests/browser_smoke.py`.

**Проверено на момент разделения:** исходный JavaScript и CSS не изменены ни на один байт; 6 интеграционных проверок Python; `node --check` собранного JS; тесты в изолированном Chromium на настольном и мобильном viewport — главное меню, запуск первого уровня, 10 видов оружия, 18 архитектурных тем, наличие миссии и диагностик, нулевые ошибки JavaScript. Во время тестов Chromium использовал **Canvas fallback**, поэтому WebGL и фактический Android-браузер этим тестом не подтверждены.

## При изменении игры

1. Найти нужные имена и функции через `SOURCE_NAVIGATION_RU.md` и `src/manifest.json`.
2. Изменить **исходные** `src/*.js` и при необходимости `styles/*.css`.
3. Выполнить `python tools/build.py` (или `REBUILD.bat`). Убедиться, что `dist/game.js` и `index.html` обновились.
4. Проверить `python tools/build.py --check`, `python tests/test_integrity.py`; по возможности — `python tests/browser_smoke.py`. Отдельный `tests/test_original_baseline.py` запускается только для доказательства неизменности **исходной** игры, поэтому после намеренных изменений он уже не подходит.
5. Запустить `PACKAGE.bat` / `python tools/package.py`: получить **один ZIP** со всеми файлами, проверенными SHA-256 и `index.html` в корне. В архиве следует сохранять исходник, манифест, сборщик, тесты и исходный эталон.

**Важно:** тест `--verify-original` и `tests/test_original_baseline.py` по замыслу проходят только пока исходная игра не изменена. Постоянный `tests/test_integrity.py` **не привязан** к старому JavaScript: он проверяет правильность текущей модульной сборки после обновлений и ловит пропущенные файлы, отсутствие пересборки и опасный литерал `</script>` внутри HTML.

## Сохранения на мобильных устройствах

`localStorage` не является частью ZIP и при смене пути/происхождения файла может быть недоступен. Экспорт JSON из старой игры и импорт в новой нужен для надежного переноса прогресса. Само имя `index.html` не переносит сохранённый прогресс.
