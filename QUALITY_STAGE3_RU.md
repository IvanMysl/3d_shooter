# Отчёт о качестве этапа 3 — физика видимых препятствий

## Что проверено автоматически

1. Модульная сборка, все 31 JS-часть в исходном порядке, идентичные DOM-id в `index.html` и `dev.html`, отсутствие потерянных файлов.
2. Тесты базовой баллистики: пол, лестницы, потолки, плиты мостов, объёмные хитбоксы роботов, защитная прочность и пробиваемость.
3. Новые проверки статической геометрии: перила, колонны, прострел из соседних клеток, пересечение лучом, 3D радиус снаряда, точка контакта, полное обрезание декали до прямоугольной грани, очистка старых коллизий при пересборке и отсутствие невидимых препятствий в Canvas fallback.
4. **Интеграция с настоящим `createWorldMesh`:** без GPU, при отключенной растеризации треугольников, используется тот же код построения 3D-геометрии, который работает на WebGL. Проверены объёмные перила, возвышенные мосты, проходимость перехода, нижний проход под мостом, пять архитектурных стилей и переключение качества.
5. Браузерные тесты `index.html` и `dev.html`, ПК и мобильные размеры: запуск первого уровня, количество оружия/тем, существующие улучшения, старые сохранения, броня, мультитач, F5, объёмные лучи в Canvas fallback, отсутствие исключений JS.
6. ZIP: `index.html` строго в корне и самодостаточен; каждый файл проверен по SHA-256, архив проходит CRC.

## Что ещё требует ручной проверки

1. В Android Chrome и на ПК откройте игру через GitHub Pages. Проверьте, что 3D отрисовка действительно работает: тестовый Chromium использовал запасной Canvas-рендер.
2. На уровне с высоким мостом проверьте стрельбу по перилам, опорам и балкам из ракетницы, в том числе со стороны нижнего прохода; визуальный взрыв должен быть на поверхности, а не внутри металла.
3. Попробуйте стрелять точно вниз в лестницы и пол, затем под углом вдоль края ступени. Крупный вражеский шар не должен проходить через металл, если касается его своим радиусом.
4. Пробегите по верхнему мосту, затем под ним; проверьте прыжок головой в нижнюю поверхность моста и плавность движения у опор.
5. Переключайте первое/третье лицо F5, в мобильной версии — кнопкой «ВИД», рядом с ограждениями и стенами. Камера не должна проходить сквозь балки.
6. Длительно постреляйте по углам стен и узким перилам, оцените отсутствие выступающих за грани «наклеек» от пуль.
7. На Android проверьте FPS и потребление памяти в длинной сессии, особенно на тяжёлых архитектурах и высоком качестве графики. При ухудшении производительности можно отдельно профилировать количество проверяемых ячеек.

### Диагностика WebGL

На ПК в DevTools (F12, Console) после запуска уровня можно выполнить:

```js
window.__neonTest.worldSolids()
```

Если браузер использует WebGL, должны быть `webgl: true` и положительное `boxes`. При Canvas fallback будет `webgl: false`, `boxes: 0`, и отсутствие WebGL-объёмов является ожидаемым: в таком режиме сами декорации не рисуются.

Для проверки попадания луча из выбранной мировой точки:

```js
window.__neonTest.traceWorld(15.5, 2.8, 14.5, 0, 0, -1, 5, 0.2)
```

Последний параметр `0.2` — радиус движущегося снаряда в игровых единицах. Координаты конкретного препятствия зависят от процедурной карты, приведённые числа — пример.

**Ограничения тестирования:** реальный WebGL, GPU, Android-устройство и все 99 999 процедурных вариантов кампании этой средой не проверены. Совпадение статической коробчатой геометрии и AABB проверено конструктивно, но для сферически округлых анимированных моделей нужна отдельная специализированная геометрия. Не следует считать этот выпуск доказательством полного отсутствия любых ошибок игры.
