# Stage103 — ФИЗИЧЕСКИ ТОЧНЫЕ НАЗЕМНЫЕ МАРШРУТЫ (21.11.2026)

**Каноническая база:** Stage102. **Выпуск:** `GAME_BUILD='103'`; сетевой протокол `MP_VERSION=41` не изменён. **Ориентировочная общая готовность — 98,9%** (Stage102: 98,7%; субъективная оценка, не процент тестового покрытия).

## Обнаруженные реальные несоответствия

1. **Тяжёлый робот получал маршрут маленького разведчика на основном этаже.** В Stage102 верхние галереи учитывали реальные габариты каждого NPC, но нижнее глобальное BFS-поле оставалось одинаковым для небольшого разведчика, тяжёлого корпуса и босса. Воспроизведённый пример: нарисованная и зарегистрированная как AABB стальная полоса ограничивает боковой зазор; `.22 м` разведчик проходит прямо, крупный робот физически останавливается, но старый `enemyHeading` продолжал направлять его прямо в металл.
2. **Наземная маска не учитывала добавление статики в существующий массив.** После регистрации нового `worldSolidBox` при неизменном `worldSolidGrid` ранее закэшированный тайл мог считаться свободным, хотя тело уже сталкивалось с новой стальной деталью. Так же первая четверть ребра оставалась непроверенной у исходной клетки, и тонкая стойка непосредственно в центре могла пропускаться графом. Ошибка воспроизведена на неизменённом Stage102.
3. **Общее поле наземного пути ждало таймера до обновления геометрии.** При изменении металла или состава физического оборудования в уже запущенной игре перерасчёт ожидал следующей плановой итерации (обычно до 650 мс). При движении это не позволяло пробить твёрдую стену, но выдавало некоторое время неверный указатель NPC. Теперь обновление происходит в следующем игровом кадре.

## Реализовано

- `src/13-enemy-navigation-spawn.js`: `groundChassisField`, `groundChassisEdge`: отдельные кешируемые 3D-поля для корпусов крупнее `.245 м` или выше `1.68 м`. Используются истинные `enemyBodyRadius`, `enemyBodyHeight` и фактический радиус шага, округлённые в сторону безопасности до 1 см. Реальные высоты ступеней ограничены `0.245 м`. Каждое ребро проверяется в точках `0, .25, .50, .75, 1` с настоящими `worldSolidBodyCollision`. Обычные разведчики сохраняют быстрое общее BFS-поле. Поля кэшируются по клетке цели, классу размеров, игре, карте, статике и её счётчику, индексам оборудования и ревизии уничтоженных реакторов; хранится не более восьми профилей.
- Если металлический узел закрывает клетку игрока для босса, строится подход к свободным соседним клеткам радиуса двух шагов. В полностью физически изолированной области **не придумывается** невозможный путь: крупный враг не должен проходить сквозь металл.
- `src/13a-enemy-world-navigation.js`: исправлена инвалидизация стандартных наземных тайлов/рёбер при изменении числа 3D-коллайдеров, карты высот и игровой сессии; проверяются также исходная клетка и оба края ребра.
- `src/19-gameplay-update.js`: общее поле перестраивается при смене физического мира или оборудования, а не только по таймеру/уничтожению реактора.
- `src/27-main-loop-diagnostics.js`: `__neonTest.groundChassisPhysics()` — неразрушающая браузерная QA на настоящих картах, три габарита роботов, проверки достижимых рёбер и честная отметка физически непроходимых областей.
- `src/00-core-save.js`: версия Stage103. `MP_VERSION=41` неизменен.

## Что физически НЕ изменялось

**Новых стен, невидимых коллайдеров или нефизических декораций нет.** `src/04-map-generation.js`, `src/04a-static-world-solids.js`, `src/05-world-mesh.js`, все Canvas/WebGL-рендереры, геометрия 100 карт, высоты мостов и лестниц, 3D AABB, баллистика, оружие, миссии, сериализация сохранений и сетевые модули побайтово прежние относительно Stage102. Уточнено только чтение существующих физических препятствий алгоритмом NPC.

## Производительность и ограничения

В headless Chromium Canvas на трёх выбранных уровнях холодный **диагностический** расчёт трёх профилей занимал приблизительно 15–22 мс, повторный на кэше — 1–2 мс (условия конкретного тестового компьютера, **не** показатели Android). В реальном GPU WebGL, на Android и при нагрузке большого числа противников эти цифры не измерены. Новая версия повышает строгость BFS и может менять поведение врагов в узких проходах; такой проход иногда физически доступен только разведчику.

**НЕ проведены:** монолитный крайне долгий `tools/package.py main()` с полным историческим набором тестов; настоящая GPU WebGL на Windows/Android; измерение FPS и нагрева на телефоне; сетевой матч между двумя физическими устройствами; ручное прохождение 100 уровней. Один объединённый запуск браузерных регрессий был прерван по времени после успешных Stage103, smoke, Stage101 и Stage102; незавершённый Stage100 браузерный сценарий не учитывается в итоговой статистике. Тесты перечислены без гарантии абсолютного отсутствия ошибок.

## Для воспроизведения

```bash
python tools/build.py
python tools/build.py --check
node tests/test_stage103_ground_chassis_routes.cjs
node tests/test_stage103_ground_nav_revisions.cjs
LEVELS=1,2,3,4,5 node tests/test_stage103_actual_ground_profiles.cjs
python tests/browser_stage103_ground_chassis.py
python tests/test_integrity.py
python -m unittest discover -s tests -p 'test_*.py'
```

В PowerShell для диапазонов задавайте `$env:LEVELS=(1..25) -join ','`, затем запускайте Node-скрипт. Оффлайн `index.html` запускается напрямую, `dev.html` — модульный вариант без сетевых зависимостей.
