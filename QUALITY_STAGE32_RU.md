# Контроль качества — Stage32: безопасные обновления и сохранения

## Что изменено

- Сборка оставлена **автономной**: один готовый `index.html`, отдельные JS/CSS-модули для разработки, никаких обязательных запросов на запуске.
- Маркер `V32` есть на каждом экране меню. Из открытого GitHub Pages можно перейти по адресу с `?v=32` без изменения домена и области хранения игры.
- Старые `neonrift3d-save` и `neonrift3d-save-backup` используются **только для первого переноса**; они не удаляются. Новая защищённая ветка `neonrift3d-save-protected-v1` при последующих загрузках имеет приоритет перед старым хранилищем.
- Старая вкладка больше не может перезаписать защищённое сохранение. Новая вкладка Stage32 обнаруживает появление более новой записи в защищённом хранилище (`storage` event плюс повторная проверка перед каждой записью) и блокирует конфликтующую запись.
- При конфликте показываются кнопки экспорта локального состояния и загрузки актуальных данных, а бой приостанавливается. Более позднее отдельное изменение из Stage31 не импортируется автоматически: показывается объяснение, как перенести его по JSON.
- Вторая локальная резервная копия хранит **предыдущее** корректное сохранение; прежде основной и резервный ключ переписывались идентично.
- Импорт всегда требует подтверждения замены и пишет защищённое сохранение принудительно только после явного согласия. При неудачной записи восстанавливается текущий объект прогресса.

## Автоматические проверки

- `node tests/test_stage32_update_save_guard.cjs` — **48 проверок**: миграция Stage31, все 12 постоянных рангов, бронекостюмы, ранги оружия и полёта, контрольная точка с наградами, предыдущая резервная копия и восстановление повреждённой основной записи, защита от старой версии, блокировка двух активных вкладок, предупреждение с паузой во время боя, экспорт конфликтующей вкладки, подтверждение импорта, URL `?v=32`, отображение версии, офлайн-поведение.
- Регрессии Stage1–31 и проверки 100 уровней выполняются через `python tools/package.py --output ...`.
- Полная сборка и все доступные структурные/Node/Python-тесты прошли без ошибок. Chromium smoke не удалось выполнить в этой среде: запуск браузера блокируется системным запретом `socket() Operation not permitted`. Реальный Android/планшет также требует ручной проверки.

## Ограничения и поведение

- Изменение `?v=` заставляет браузер использовать другую запись HTTP-кэша, но **не заменяет публикацию**: GitHub Pages должен сначала завершить деплой. Следующему выпуску нужен новый параметр, например `?v=33`.
- Хранилища разделены по браузеру, устройству и происхождению страницы. При очистке данных сайта или переезде на другой домен необходим JSON-экспорт/импорт.
- Защищённый прогресс **не объединяется** автоматически с действиями игрока в старой версии после миграции: ручной импорт JSON является явным выбором, который заменяет текущее сохранение. Это защита от незаметного удаления новых веток улучшений.
- Одновременные записи в одном `localStorage` не являются транзакцией; проверка перед записью и событие `storage` значительно снижают риск, но абсолютную атомарность между вкладками может дать только отдельное транзакционное хранилище. Для важных данных всегда оставляйте JSON-копию.
- Публикация на GitHub Pages не выполняется автоматически при сборке архива.
