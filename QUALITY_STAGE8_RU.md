# Этап 8 — проверка физического укрытия, ударов и лечения

## Автоматические тесты

```bash
python tools/build.py --check
python tests/test_integrity.py
node tests/test_stage8_enemy_cover.cjs
python tests/browser_stage8.py
python tools/package.py --output ../NEON_RIFT_3D_STAGE8_ENEMY_COVER_2026-11-12.zip
```

`test_stage8_enemy_cover.cjs` выполняет настоящую функцию `updateEnemies` со строгими заглушками стен и проверяет: ближнюю атаку разведчика, удар босса с отдельным таймером, отсутствие атак оглушённого босса, ударную волну через укрытие, исцеление за перегородкой, дальнобойного стрелка, отсутствие задержки регенерации при неуязвимости, эволюцию защиты командира. Это модульное тестирование, а не симуляция настоящей GPU-сцены.

`browser_stage8.py` запускает обе сборки на двух размерах экрана, берёт настоящую карту и трассирует существующую стену между открытыми клетками и открытую линию. Тестовая среда Chromium использует **Canvas fallback**, не реальный WebGL.

## Приёмка на GitHub Pages / Android / WebGL

1. Экспортируйте сохранение из предыдущей игры. Залейте новый распакованный ZIP на GitHub Pages, обновите страницу и импортируйте сохранение.
2. На карте с узкими металлическими перегородками и перилами стойте у одного края, а врага оставьте по другую сторону. Робот не должен наносить контактный урон через преграду, если он не может подойти к корпусу игрока напрямую.
3. Босс на пятом уровне: в упор без преграды он наносит периодический контактный урон, но не каждый кадр; при наличии стены/перила между боссом и игроком контактного урона быть не должно.
4. Доведите босса до третьей фазы. Спрячьтесь от напольной волны за толстой стеной; сравните с открытой площадкой, соблюдая условия близости и уровня высоты.
5. Проверьте медика: за толстой перегородкой он не должен лечить союзника, за открытой линией — должен.
6. Проверьте после загрузки старого сохранения покупки/уровни оружия, 12 костюмов, F5/кнопку ВИД, мобильный бег, открытие арсенала вторым пальцем, подъем на мосты, ракеты и снаряды босса.
7. На настоящем Android проверьте скорость FPS при десятках врагов и реакцию на сон/возобновление приложения; сравните с этапом 7.

## Известные ограничения

- Проверена логика урона и 2D-Canvas-браузер; аппаратная 3D-отрисовка и реальный Android в данной среде недоступны.
- Движение NPC ещё использует клеточный навигационный слой и **не полностью учитывает** тонкие статические декорации. Их урон/прицеливание учитывают физическое укрытие, но физическое движение NPC потребует отдельного, осторожного изменения навигации, чтобы не сделать уровни непроходимыми.
- Точные треугольные коллайдеры анимированных частей роботов отсутствуют; используются прокси-эллипсоиды, привязанные к анимации.
