# NEON RIFT 3D — модульная рабочая версия

**Запуск игры:** распакуйте ZIP и откройте **`index.html`** в браузере. Это **полностью автономная сборка в одном HTML-файле**: встроены весь JS и CSS, никакие соседние файлы для её запуска не нужны. Интернет, Python, Node.js, веб-сервер или установка библиотек **не требуются для игры**. Это сохраняет совместимость с Android, где открытие соседних `*.js` из файлового менеджера иногда ограничено.

**Для запуска достаточно одного `index.html`**, но **для последующей разработки храните весь ZIP**: в нём модульные исходники, сборщик и контрольные тесты.

## Что где находится

| Путь | Для чего |
|---|---|
| `index.html` | **Полностью автономный файл запуска**. Собран из модулей, при первом переносе побайтово совпадает с оригиналом. |
| `dev.html` | Компактная HTML-страница, подключающая `dist/game.js` и файлы из `styles/`; удобна для проверки CSS/JS в браузере, разрешающем локальные файлы. |
| `src/*.js` | **28 исходных логических частей**, здесь мы редактируем игру. |
| `src/manifest.json` | Порядок исходников, границы разделов, контрольные хеши. |
| `src/_wrapper-prefix.txt` и `_wrapper-suffix.txt` | Оболочка исходной самовызывающейся функции (`IIFE`), необходимая для точного совпадения с оригиналом. |
| `styles/00-*.css` ... `styles/70-*.css` | **8 отдельных исходных CSS-файлов**. В `dev.html` подключаются напрямую, а в автономный `index.html` встраиваются при сборке. |
| `dist/game.js` | Собранный исполняемый файл для `dev.html`; при изменении `src` пересобирается скриптом. |
| `tools/index-template.html` | Шаблон автономного HTML, без изменений в интерфейсе игры. |
| `dist/legacy-notes.js` | Второй оригинальный служебный `<script>` с комментарием, без изменений. |
| `tools/build.py` | Сборка и проверка **без внешних библиотек**, через стандартный Python. |
| `REBUILD.bat` | Запуск сборки двойным щелчком в Windows при наличии Python. |
| `PACKAGE.bat` | Автоматически собрать, проверить и упаковать полный проект в один ZIP (Windows). |
| `tools/package.py` | Создание ZIP с проверками и новыми контрольными SHA-256 из текущих модулей. |
| `reference/NEON_RIFT_3D_FPS_CONTROL_ORIGINAL.html` | **Нетронутый оригинал** для проверки и отката. |
| `tests/` | Проверки исходников, структурной полноты, сборки и браузерный smoke-test. |

## Почему нужен `dist/game.js`

Исходная игра целиком использует общую область видимости внутри `(()=>{'use strict'; ...})();`. Если просто разнести фрагменты по разным `<script>`, часть переменных и объявлений окажется в другой области видимости, что может сломать игру. Модульные файлы `src/*.js` — последовательные **побайтово точные фрагменты оригинального тела функции**, без переделки логики. Сборщик соединяет их в **тот же JS, который был в оригинале**, в неизменном порядке, а затем встраивает вместе с CSS в автономный `index.html`. Это одновременно сохраняет поведение и позволяет удобно редактировать отдельные системы.

**После редактирования JS или CSS** запустите `REBUILD.bat` (Windows) или `python tools/build.py` (любая ОС), а затем откройте `index.html`. Сборщик обновляет одновременно `dist/game.js` и автономный `index.html`. В `dev.html` исходные CSS подключаются непосредственно, поэтому **при использовании только `dev.html`** изменение CSS не требует пересборки. Без пересборки изменения в `src/*.js` или в CSS не попадут в автономный `index.html`.

## Проверки

```bash
python tools/build.py --check
python tests/test_integrity.py
# Только для исходной версии (до изменений игры):
python tests/test_original_baseline.py
# Дополнительные браузерные тесты при наличии Playwright/Chromium:
python tests/browser_smoke.py
```

`--verify-original` и `tests/test_original_baseline.py` нужны именно для первоначального разделения: после планового редактирования механик JS **не должен** совпадать со старым эталоном. При дальнейшей разработке используйте `--check` и **`tests/test_integrity.py`**, которые продолжают работать после любых корректных изменений исходников. Они проверяют, что изменения действительно включены в собранную игру, а пропущенный в манифесте исходник не останется незамеченным. Опциональный браузерный тест требует Playwright/Chromium **только от разработчика**.

**Подготовка ZIP после разработки:** `PACKAGE.bat` на Windows либо `python tools/package.py --output NEON_RIFT_3D_MODULAR.zip`. Упаковщик пересобирает `index.html`, запускает 9 проверок, пересчитывает `SHA256SUMS.txt` и сохраняет единый ZIP, в котором **`index.html` лежит в корне**. По желанию добавьте `--browser-tests` для 4 браузерных сценариев. При каждом следующем изменении используйте упаковщик вместо ручного копирования файлов.

## Сохранения игры

Игра сохраняет прогресс в браузере (`localStorage`, ключ `neonrift3d-save` и резервные данные) и поддерживает экспорт/импорт прогресса. **Смена пути с первоначального одиночного HTML на `index.html` может поменять локальное хранилище**, особенно при запуске с `file://`. Поэтому перед переходом в новую версию **экспортируйте прогресс в JSON из старой игры**, а в новой импортируйте его. Архив исходников сам по себе не содержит прогресс браузера.
