# Как обновлять NEON RIFT 3D на GitHub Pages без потери прогресса

## Актуальная публикация Stage35 / MP-3

Соберите `index.html` из Stage35, опубликуйте его в корне репозитория `3d_shooter`, дождитесь завершения Pages/Actions и откройте [https://ivanmysl.github.io/3d_shooter/?v=35](https://ivanmysl.github.io/3d_shooter/?v=35). В меню должна быть метка **V35**. Перед обновлением экспортируйте JSON одиночной кампании. Если раньше вручную настраивали свой публичный ключ Metered, повторно внесите его в `src/21b-multiplayer-lobby.js` **перед** `python tools/build.py` — в готовом архиве ключ отсутствует. Для сетевой тренировки зайдите в лобби с двух устройств и нажмите «Готов» на каждом, затем ведущий выберет «Начать тренировку». Это не боевой PvP-режим.

## Первое обновление до Stage32

1. Откройте прежнюю игру и нажмите **«Экспорт прогресса»**. Сохраните JSON. Не очищайте данные сайта в настройках телефона или ПК.
2. Закройте старые вкладки игры, чтобы старый код не продолжал сохранять собственное состояние.
3. Из нового архива загрузите **`index.html` из корня** в репозиторий `3d_shooter`, ветка `main`, папка `/ (root)`. Файлы `src/`, `styles/` и `tools/` нужны для разработки, но для обычной игры на Pages достаточно `index.html`.
4. Дождитесь успешного завершения **Pages → Actions → pages build and deployment**.
5. Откройте **https://ivanmysl.github.io/3d_shooter/?v=32** и проверьте отметку **V32** в игре. Данные в `localStorage` у `/3d_shooter/` и `/3d_shooter/?v=32` общие, потому что домен и протокол одинаковые.
6. Проверьте купленную броню, её ранги и полёт, все исследования, улучшения оружия и карту уровней. В первый запуск Stage32 автоматически переносит прежнее сохранение. Если что-то не совпало, сохранённый JSON можно импортировать обратно.

## Каждое следующее обновление

- Публикуйте новый `index.html` после сборки, дождитесь **успешного деплоя** и открывайте адрес с **новым** номером: `?v=33`, `?v=34` и так далее.
- Старые вкладки лучше закрывать. Ориентируйтесь на номер **Vxx** в самой игре, а не на дату загрузки репозитория.
- Если открыть новый адрес раньше завершения деплоя, он может загрузить прежний HTML. Дождитесь завершения публикации и повторите загрузку; при необходимости используйте новый параметр, например `?v=32-2`.
- Не используйте очистку «данных сайта» или смену домена как способ сбросить кэш: это может стереть браузерное хранилище с покупками. `?v=` меняет только адрес запроса и не меняет область `localStorage`.

## Если старый браузер открыл старую версию

Stage32 сохраняет прогресс в отдельном защищённом журнале. Старая вкладка может изменять **старый** журнал, но больше не перезаписывает защищённый. Изменения обеих веток автоматически не объединяются: если нужно перенести сделанные в старой версии покупки, экспортируйте JSON из старой версии и импортируйте в Stage32, предварительно сохранив текущий JSON Stage32.

## Важные ограничения

Без сетевого запроса браузер не может сам догадаться, что на GitHub уже лежит новый HTML. Игра остаётся автономной и **не выполняет фоновых запросов для проверки обновлений**. Версионированная ссылка не устраняет задержку деплоя самого GitHub Pages.
